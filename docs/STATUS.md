## Facts learned (keep in mind)

- The site names (Round Rock, Pflugerville, Georgetown, Hutto), LTS RFID, AutoStore, and the CO27 picking-list cadence are fictional choices for the synthetic data; they do not mirror any real company's setup (the owner, 2026-10-29).
- Each generator component draws from its own random stream (`default_rng([seed, component])`); new components must use a new component number so existing tables stay byte-identical and reference answers stay valid. Numbers in use: master data 1–7, outbound orders, deliveries, waves and tasks 10, A5 grants 12, operator assignment 13 (one stream per site), goods issue 14, AutoStore ports and system confirmations 15, inventory 20 and 21, inbound 30, AutoStore 40, RFID 50, trade 60, manufacturing 70, planning data 80. A scenario that draws inside an existing generator must use its own stream, and a draw whose count depends on a scenario (A4 changes Round Rock's wave count and task times) must be made on the scenario-free basis and remapped afterwards, or every later draw shifts; 0.7.0 split the outbound stages into their own streams for that reason (a one-time change of operators, resources, holds, reversals, and transit noise at every site).
- `scwm_ordim_c` holds picks (`2010`/`2020`) and putaways (`1011`); every task query must filter by process type.
- Reference SQL: avoid correlated scalar subqueries over a CTE with `ORDER BY ... LIMIT`; Databricks may evaluate the CTE again and pick another row (c144). Verify multi-step references with an independent query.
- The AutoStore controller tables (`raw_ext.autostore_*`) use Longgang local time (`TIMESTAMP_NTZ`); EWM is UTC.
- `eval.*` tables are hidden by the tool server (`HIDDEN_LAYERS`): the guard answers `UNKNOWN_TABLE`, and `list_tables` never shows them.
- Scenario post-processing that must not change ECC documents derives new data from existing facts (trade licenses from the outbound holds, A6 copies appended after all generators) or changes only fields no other generator reads (A7 sales units, no random draws).
- Polars `is_between("a", "b")` treats strings as column names; wrap literal bounds in `pl.lit`.
- PI 0.87.1 sends `thinking.display: "summarized"` by default, so thinking summaries arrive without extra configuration. For models with per-message effort (Opus 5.5), PI sends top-level `output_config.effort = "high"` and puts the configured effort in a trailing effort-only system message, which takes precedence; the `request` trace event resolves this (`effort_source`).

- Metric views: YAML 1.1 deploys on Free Edition with `CREATE OR REPLACE VIEW ... WITH METRICS LANGUAGE YAML AS $$...$$`; `GRANT SELECT ON TABLE` works on them and they appear in `information_schema.table_privileges`.
